# 📋 Спецификация Seller Bot — новая логика

> Статус: target-state spec с частично реализованными изменениями.
> Текущая реализация уже использует hybrid chat model (bot + Mini App) и payout requests через `SellerWithdrawal` в main DB. Legacy `withdrawal-tasks` routes сохранены только как compatibility alias.

## 1. Онбординг (вход селлера)

### 1.1 Выбор языка
При первом входе `/start`:
- **Языки:** 中文 (Chinese) | Русский | English
- Кнопки выбора языка → сохраняем в `sellers.language`

### 1.2 Правила
После выбора языка показываем:
- Текст правил (по языку)
- Объяснение депозита (это залог, не сбор!):
  - Banks: $100, CC: $50
  - Деньги остаются на балансе селлера — можно вывести. Нужны как гарантия качества и покрытие споров.
- Кнопки: **✅ Принимаю** | **❌ Отклоняю**
- При принятии → `sellers.rules_accepted = True`
- Без принятия — панель недоступна

### 1.3 Регистрация
- После правил → заявка на регистрацию
- Админ одобряет → селлер получает доступ к панели

## 2. Панель селлера (после одобрения)

### 2.1 Главное меню
```
📦 Мои товары

📊 Статистика
💸 Вывод средств
💬 Сообщения (N)

```

### 2.2 Загрузка товаров — типы материала

| Тип | Подтипы | Параметры |
|-----|---------|-----------|
| **CC** | with zip (опционально) / with fullz | Строки, массовая валидация, понятная инструкция |
| **Bank** | brute / selfreg / log | Zip, разные названия в готовые категории |
| **Enrol** | — | Почти как bank |

**Структура выбора:**
1. Тип: CC | Bank | Enrol
2. Подтип (для CC): with_zip | with_fullz
3. Подтип (для Bank): brute | selfreg | log
4. Категория (из готовых)
5. Параметры товара (цена, описание, инструкция)
6. Submit

## 2.3 Помощники селлера

Селлер должен иметь возможность добавить помощников для двух задач:

- загрузка товаров
- поддержка / ответы покупателям

### Роли помощников

| Роль | Что может | Что не может |
|------|-----------|--------------|
| `upload_helper` | загружать товары, редактировать свои черновики, отправлять на модерацию | не видит вывод средств, не меняет депозит, не закрывает dispute |
| `support_helper` | отвечать в чатах покупателей, отправлять документы, эскалировать в support | не загружает товары, не выводит средства, не подтверждает payout |
| `manager_helper` | делать и загрузку, и поддержку, видеть список товаров/чатов | не может выводить средства без owner, не может менять owner |

### Можно ли сделать одного помощника на всё

Да.

Если seller хочет одного человека на все задачи, ему можно выдать роль:

- `manager_helper`

Этот helper сможет:

- загружать товары
- редактировать черновики
- отправлять товары на модерацию
- отвечать в buyer chats
- отправлять документы
- эскалировать кейсы в support/moderation

Но даже такой helper по умолчанию не должен иметь доступ к:

- выводу средств
- депозиту
- смене owner
- финальному закрытию dispute

### Можно ли добавить несколько helpers под разные задачи

Да.

Один seller может добавить несколько помощников одновременно.

Пример:

- helper A -> только `upload_helper`
- helper B -> только `support_helper`
- helper C -> `manager_helper`

Это и есть рекомендуемая модель для командной работы.

### Рекомендуемое ограничение по количеству

Простая версия:

- до `10` active helpers на одного seller

Позже лимит можно сделать:

- по тарифу
- по депозиту
- по ручному решению админа

### Главные правила

- у каждого seller есть один `owner`
- owner может добавить несколько helpers
- helper работает только внутри одного seller-аккаунта
- все действия helper должны логироваться
- buyer не обязан знать, что отвечает helper, но система должна знать кто именно отвечал

### Как добавлять helper

Flow:

1. owner открывает `👥 Помощники`
2. жмёт `Add Helper`
3. выбирает роль:
   - `Upload`
   - `Support`
   - `Manager`
4. вводит `@username` или `telegram_id`
5. система создаёт invite
6. helper открывает bot и принимает приглашение
7. owner подтверждает подключение

Рекомендуемые кнопки:

- `Add Helper`
- `Active Helpers`
- `Pending Invites`
- `Remove Helper`
- `Change Role`
- `Block Helper`
- `Assign All Tasks`
- `Assign Support Only`
- `Assign Upload Only`

### Что должен видеть owner

Для каждого helper:

- имя / username
- роль
- статус `pending / active / blocked`
- когда был добавлен
- кто добавил
- последнее действие

### Что должен видеть helper

После входа helper должен видеть только разрешённые разделы.

Примеры:

- `upload_helper` -> `Мои загрузки`, `Черновики`, `На модерации`
- `support_helper` -> `Сообщения`, `Чаты`, `Эскалации`
- `manager_helper` -> `Товары`, `Сообщения`, `Помощники (read-only или limited)`

Если owner выбрал модель "один помощник на всё", то helper видит:

- `Товары`
- `Загрузки`
- `Сообщения`
- `Чаты`
- `Модерация по своим кейсам`

Если owner выбрал модель "несколько helpers", то каждый видит только свою роль.

### Запрещённые действия для helper по умолчанию

- вывод средств
- просмотр/изменение депозитного баланса
- смена owner
- удаление истории заказов
- принятие финального решения по dispute без support/moderation
- доступ к чужим seller-командам

### Audit log

Каждое действие helper нужно писать в аудит:

- кто сделал
- роль
- seller_id
- действие
- object_type
- object_id
- timestamp

Примеры событий:

- `helper_uploaded_item`
- `helper_edited_draft`
- `helper_sent_message`
- `helper_escalated_chat`
- `helper_blocked`

### Уведомления owner

Owner должен получать важные действия helper:

- helper uploaded new item
- helper sent item to moderation
- helper replied in buyer chat
- helper escalated case to support
- helper was blocked/unlinked

### Правило безопасности

Если helper нарушает правила качества:

- warning идёт не только helper, но и owner seller-а
- owner несёт ответственность за свою команду
- support/moderation может отключить отдельного helper без блокировки всего seller-а
- при системных нарушениях может блокироваться весь seller account

## 6. Максимально удобная связь с клиентом

### 6.1 Централизованный чат
- **Список чатов** — все заказы с непрочитанными сверху
- **Один экран** — история + быстрые ответы + кнопки
- **Push** — при новом сообщении сразу уведомление с кнопкой «Ответить»

### 6.1A Кто может отвечать

В чатах могут отвечать:

- owner seller
- `support_helper`
- `manager_helper`

`upload_helper` не должен иметь доступ к buyer chats.

### 6.1B Что видит buyer

Buyer общается с витриной seller-а, а не с конкретным helper.

Внешняя логика:

- buyer пишет seller
- ответ может отправить owner или helper
- если кейс спорный, он эскалируется в `support/moderation`

При этом внутри системы должно быть видно:

- кто именно ответил
- owner это или helper
- была ли эскалация

### 6.2 Быстрые ответы (уже есть)
- Селлер: «Got it», «Soon», «Info», «Done»
- Покупатель: «When ready?», «Status?», «Got it»

### 6.3 Улучшения
1. **Кнопка Reply** в каждом push от покупателя (уже добавлена)
2. **Группировка** — «Активные чаты» (есть непрочитанные) отдельно
3. **Шаблоны** — селлер может добавить свои (опционально)
4. **Файлы** — поддержка фото/документов (уже есть)
5. **Распределение по роли** — support helpers видят только support-чаты, manager видит все

### 6.4 Уведомление о новом сообщении
- Сейчас: при открытии «Messages» видит список
- Нужно: **мгновенный push** при каждом сообщении от покупателя с кнопкой «💬 Open Chat»
