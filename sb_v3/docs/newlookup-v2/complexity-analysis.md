# NewLookup — Анализ сложности и упрощения

## Что есть сейчас (код)
- 7 ботов (main, seller, support, worker, marketer, mirror × N) + web panel + lookup API
- Единая SQLite БД (newlookup.db) — все пишут в один файл
- Shared модуль (database, models, services)
- Mini App на React/TypeScript (seller-mini-app-v2)
- Admin Panel на Jinja2 templates + JS
- i18n: EN/RU (частично), ES/ZH — НЕТ

## Что добавляем
1. Реферальная система (5 уровней, двойные %, модерация)
2. Mirror Bot — типы заказов (Order/Order+Catalog/Catalog) + ETA
3. Admin — рассылки 4 языка, заказы по видам, каталог, role-based
4. Mini App Upload — полная переработка 10 разделов + модерация
5. Seller Bot — онбординг, депозит, уведомления

## Критические сложные моменты

### ~~🔴 1. SQLite конкурентность~~ → НЕ АКТУАЛЬНО
- SQLite — только для локального теста. На проде будет Postgres/MySQL.
- Код уже на SQLAlchemy — миграция на Postgres = смена connection string в .env.

### 🔴 2. i18n ES/ZH — огромный объём текстов
- Сейчас EN/RU частично. Добавить ES/ZH = перевести ВСЁ UI + все инструкции + все уведомления
- **Упрощение:** Использовать LLM API для автоперевода текстов. Хранить в JSON-файлах по языкам. Админ правит вручную если нужно.

### 🔴 3. Mini App Upload — 10 разделов с разной логикой
- Banks, Brute Bank, CC, NFC, OTP, Selfreg CC, Enrollment, Logs, Checks, Selfreg BA
- Каждый с модерацией, инструкциями, валидацией
- **Упрощение:** Единый компонент UploadForm с конфигом по категории (JSON). Не 10 отдельных компонентов, а 1 параметризованный.

### 🟡 4. Реферальная система — 5 уровней
- Рекурсивный подсчёт цепочки рефералов при каждой покупке
- **Упрощение:** Хранить parent chain (массив до 5 ID) в поле referral_chain при регистрации. При покупке — один SELECT, не рекурсия.

### 🟡 5. Рассылки по будильнику на 4 языках
- Scheduler + шаблоны × 4 языка × 3 бота = 12 конфигураций
- **Упрощение:** Один шаблон рассылки в админке → автоперевод на 4 языка → превью → отправка. Не 12 отдельных форм.

### 🟡 6. Хардкод Docker-имён в HTTP-вызовах
- `http://main_bot:8080` вместо ENV
- **Упрощение:** Один .env блок `SERVICE_URLS` — заменить за 30 минут.

### 🟢 7. Role-based доступ в админке
- 4 роли уже есть в БД (owner, moderator, accountant, manager)
- **Упрощение:** Декоратор `@require_role("owner")` на роутах. Фронт скрывает пункты меню по роли из сессии.

## Ключевые упрощения (экономия ~40% времени)

1. **Upload:** 1 параметризованный компонент вместо 10 отдельных
2. **i18n:** LLM-автоперевод вместо ручного перевода
3. **Рассылки:** 1 шаблон → автоперевод на 4 языка вместо 12 форм
4. **Рефералы:** parent_chain массив вместо рекурсии
5. **Role-based:** Декоратор + скрытие меню вместо полной системы прав
