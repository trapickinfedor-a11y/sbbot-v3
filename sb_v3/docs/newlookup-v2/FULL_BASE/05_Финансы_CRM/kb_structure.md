## Архитектура базы знаний в NocoDB

### Таблица 1: «Статьи базы знаний» (kb_articles)

Основная таблица для хранения всех статей, инструкций и регламентов.

| Название поля | Тип поля (Field Type) | Описание |
|---|---|---|
| `ID статьи` | `ID` | Уникальный идентификатор. |
| `Название статьи` | `Single line text` | Заголовок статьи. **Сделать Display Value**. |
| `Содержание` | `Long text` | Основной текст статьи. **Включить поддержку Markdown**. |
| `Статус` | `Single select` | Опции: "Черновик", "Опубликовано", "Архив". |
| `Дата создания` | `Created time` | Автоматически фиксирует дату создания. |
| `Дата обновления` | `Last modified time` | Автоматически фиксирует дату последнего изменения. |
| `Теги` | `Multi-select` | Ключевые слова для быстрого поиска (например, "CRM", "отчет", "скрипт"). |

### Таблица 2: «Категории» (kb_categories)

Для создания иерархической структуры документации.

| Название поля | Тип поля (Field Type) | Описание |
|---|---|---|
| `ID категории` | `ID` | Уникальный идентификатор. |
| `Название категории` | `Single line text` | Например, "Работа с CRM", "Продукты компании", "Регламенты отдела продаж". **Сделать Display Value**. |
| `Описание` | `Long text` | Краткое описание содержимого категории. |

### Связи между таблицами

1.  **«Статьи» <-> «Категории»**: Каждая статья должна принадлежать одной категории.
    *   В таблице **«Статьи»** создать поле `Категория` с типом `Link to another record`, связанное с таблицей **«Категории»**.

2.  **«Статьи» <-> «Сотрудники»**: Чтобы знать, кто автор статьи.
    *   В таблице **«Статьи»** создать поле `Автор` с типом `Link to another record`, связанное с таблицей **«Сотрудники»** (из существующей CRM).

3.  **«Категории» <-> «Категории» (самореференция)**: Для создания вложенных категорий (подкатегорий).
    *   В таблице **«Категории»** создать поле `Родительская категория` с типом `Link to another record`, связанное с этой же таблицей **«Категории»**.
