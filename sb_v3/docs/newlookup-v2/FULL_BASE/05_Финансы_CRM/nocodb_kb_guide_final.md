# Руководство по созданию Базы Знаний (Wiki) в NocoDB

**Автор:** Manus AI | **Дата:** Март 2026

---

## Введение

Централизованная база знаний (внутренняя Wiki) — это критически важный инструмент для любой команды. Она позволяет хранить и систематизировать всю важную информацию: инструкции по работе с CRM, регламенты бизнес-процессов, скрипты продаж, ответы на часто задаваемые вопросы (FAQ), описания продуктов и шаблоны документов. Это снижает время на обучение новых сотрудников, обеспечивает единый стандарт работы и сохраняет ценные знания внутри компании.

Главное преимущество построения базы знаний прямо в **NocoDB** — это **единство рабочего пространства**. Вам не нужно переключаться между CRM и отдельным сервисом для документации. Все находится в одном месте, тесно связано друг с другом и управляется по единым правилам доступа.

### Что вы получите в итоге

| Компонент | Назначение |
|---|---|
| **2 новые таблицы** | «Категории БЗ» и «Статьи БЗ» с полной структурой полей |
| **Иерархия категорий** | Возможность создавать разделы и подразделы |
| **Markdown-редактор** | Форматированный текст статей с заголовками, таблицами, кодом |
| **Полнотекстовый поиск** | Быстрый поиск по названию, содержанию и тегам |
| **Интеграция с CRM** | Привязка статей к сделкам, клиентам и задачам |
| **Гибкие права доступа** | Разграничение ролей: кто читает, кто пишет, кто управляет |

## Часть 1: Создание структуры данных

Основой нашей базы знаний будут две таблицы: одна для хранения самих статей, а другая — для их категоризации. Обе таблицы создаются в том же проекте (Base), где уже находится ваша CRM.

### Таблица 1: «Категории БЗ»

Эта таблица служит для создания иерархической структуры вашей базы знаний. Думайте о ней как о разделах книги.

**Инструкция:** Нажмите `+ New Table`, назовите ее `Категории БЗ` и добавьте следующие поля:

| Название поля | Тип поля (Field Type) | Настройки / Описание |
|---|---|---|
| `ID категории` | `ID` | Генерируется автоматически. |
| `Название категории` | `Single line text` | Например: "Работа с CRM", "Продукты компании", "Регламенты продаж", "Маркетинг". **Нажмите правой кнопкой на поле → Set as Display Value**. |
| `Описание` | `Long text` | Краткое описание того, что хранится в этой категории. |
| `Родительская категория` | `Link to another record` | Свяжите с этой же таблицей `Категории БЗ`. Это позволяет создавать подкатегории (например, "Скрипты" внутри "Регламенты продаж"). |

**Примеры категорий для вашей команды:**

```
Работа с CRM
├── Инструкции по работе с клиентами
├── Инструкции по работе со сделками
└── Часто задаваемые вопросы (FAQ)

Продукты и услуги
├── Описание продуктов
└── Прайс-листы

Регламенты и процессы
├── Отдел продаж
├── Отдел маркетинга
└── Онбординг новых сотрудников

Маркетинг
├── Шаблоны писем
├── Скрипты звонков
└── Материалы для презентаций
```

### Таблица 2: «Статьи БЗ»

Здесь будут храниться все ваши статьи, инструкции и регламенты.

**Инструкция:** Создайте таблицу `Статьи БЗ` и добавьте поля:

| Название поля | Тип поля (Field Type) | Настройки / Описание |
|---|---|---|
| `ID статьи` | `ID` | Генерируется автоматически. |
| `Название статьи` | `Single line text` | Заголовок статьи. **Сделайте Display Value**. |
| `Содержание` | `Long text` | Основной текст. **Критически важно:** в настройках поля (нажмите на шестеренку) включите опцию `Enable Rich Text` / `Enable Markdown`. Это позволит форматировать текст с заголовками, таблицами, жирным шрифтом и т.д. |
| `Статус` | `Single select` | Опции: "Черновик", "Опубликовано", "Архив". |
| `Дата создания` | `Created time` | Автоматически фиксирует дату создания записи. |
| `Дата обновления` | `Last modified time` | Автоматически фиксирует дату последнего изменения. |
| `Теги` | `Multi-select` | Ключевые слова для быстрого поиска. Примеры: "CRM", "скрипт", "шаблон", "договор", "FAQ", "онбординг". |
| `Просмотров` | `Number` | Необязательное поле — можно вручную отмечать популярность статьи. |

### Настройка связей

После создания таблиц необходимо их связать.

**Связь 1: Статьи → Категории**
1.  В таблице **«Статьи БЗ»** нажмите `+` для нового поля.
2.  Назовите его `Категория`, выберите тип `Link to another record`.
3.  В поле `Table` выберите **«Категории БЗ»**.
4.  Нажмите `Save Field`.

**Связь 2: Статьи → Сотрудники (Автор)**
1.  В таблице **«Статьи БЗ»** создайте поле `Автор`.
2.  Выберите тип `Link to another record` и свяжите с таблицей **«Сотрудники»** из вашей CRM.
3.  Нажмите `Save Field`.

## Часть 2: Наполнение базы знаний

Перед настройкой представлений рекомендуется создать несколько тестовых записей, чтобы сразу видеть результат.

### Создание категорий

Перейдите в таблицу **«Категории БЗ»** и создайте несколько записей. Начните с корневых (родительских) категорий — оставьте поле `Родительская категория` пустым. Затем создайте подкатегории, указав для них родительскую.

### Написание первой статьи

Перейдите в таблицу **«Статьи БЗ»** и создайте новую запись. Нажмите на строку, чтобы открыть карточку записи. В поле `Содержание` вы увидите Markdown-редактор. Используйте следующий синтаксис для форматирования:

```markdown
## Заголовок второго уровня

Обычный абзац текста. **Жирный текст**. *Курсив*.

### Заголовок третьего уровня

| Колонка 1 | Колонка 2 |
|---|---|
| Данные 1 | Данные 2 |

> Важное примечание или цитата.

1. Первый шаг
2. Второй шаг
3. Третий шаг
```

## Часть 3: Настройка представлений для удобной работы

Стандартный Grid-вид таблицы не всегда удобен для работы с документацией. Создадим несколько специальных представлений.

### Представление 1: Каталог категорий (Gallery)

Создает визуально привлекательную главную страницу с категориями в виде карточек.

**Инструкция:**
1.  Откройте таблицу **«Категории БЗ»**.
2.  Создайте новое представление (`New View`) типа `Gallery`.
3.  Назовите его «Главная страница БЗ».
4.  Добавьте фильтр: `Родительская категория` `is empty` — чтобы отображались только корневые разделы.
5.  В настройках галереи включите отображение поля `Описание`.

Теперь при клике на карточку категории вы откроете ее детальную карточку, где увидите список всех вложенных статей.

### Представление 2: Список опубликованных статей (Grid)

Удобный список всех актуальных статей с фильтрацией и поиском.

**Инструкция:**
1.  Откройте таблицу **«Статьи БЗ»**.
2.  Создайте новое Grid-представление с названием «Опубликованные статьи».
3.  Добавьте фильтр: `Статус` `is` `Опубликовано`.
4.  Настройте сортировку: `Дата обновления` по убыванию (новые статьи вверху).
5.  Скройте поле `Содержание` (оно слишком длинное для списка) — оставьте только `Название статьи`, `Категория`, `Теги`, `Автор`, `Дата обновления`.
6.  Включите `Group by` → `Категория`, чтобы статьи были сгруппированы по разделам.

### Представление 3: Черновики (Grid)

Для авторов — список статей, которые еще не опубликованы.

**Инструкция:**
1.  Создайте новое Grid-представление «Черновики».
2.  Добавьте фильтр: `Статус` `is` `Черновик`.
3.  Это представление видно только редакторам и выше.

### Представление 4: Форма для добавления статьи (Form)

Упрощает процесс добавления новых знаний для сотрудников, которые не привыкли работать с таблицами.

**Инструкция:**
1.  Создайте новое представление типа `Form`.
2.  Назовите «Добавить статью».
3.  Перетащите в форму поля: `Название статьи`, `Содержание`, `Категория`, `Теги`.
4.  Установите значение по умолчанию для поля `Статус` = «Черновик».
5.  Нажмите `Share Form` и отправьте ссылку сотрудникам.

## Часть 4: Поиск по базе знаний

Поиск — это сердце любой базы знаний. В NocoDB есть несколько способов быстро найти нужную информацию.

### Глобальный поиск

Нажмите на иконку лупы в верхней части интерфейса NocoDB (или используйте сочетание клавиш `Ctrl+K` / `Cmd+K`). Введите ключевое слово — NocoDB будет искать по всем таблицам вашего проекта, включая названия статей.

### Поиск внутри представления

В любом Grid-представлении нажмите `Search` в правом верхнем углу и введите запрос. Это отфильтрует строки, содержащие введенный текст в видимых полях.

### Поиск по тегам

Для поиска по тегам используйте фильтры. В представлении «Опубликованные статьи» нажмите `Filter` → `+ Add Filter`:
*   `Теги` `contains` `[нужный тег]`

Это мгновенно покажет все статьи с выбранным тегом. Рекомендуется создать несколько сохраненных представлений с предустановленными фильтрами по наиболее популярным тегам.

## Часть 5: Интеграция базы знаний с CRM

Это одно из ключевых преимуществ хранения базы знаний в той же системе, что и CRM. Вы можете привязывать нужные статьи прямо к карточкам клиентов, сделок или задач.

**Инструкция:**
1.  Перейдите в таблицу **«Сделки»** (или «Клиенты», «Задачи»).
2.  Добавьте новое поле `Полезные статьи`.
3.  Выберите тип `Link to another record` → таблица **«Статьи БЗ»**.
4.  Нажмите `Save Field`.

Теперь менеджер, работая со сделкой, может прикрепить к ней нужные инструкции или скрипты. Например, к сделке на этапе «Переговоры» можно прикрепить статью «Скрипт работы с возражениями», а к новому клиенту — статью «Онбординг: первый контакт».

## Часть 6: Права доступа и управление

### Рекомендуемые роли для базы знаний

| Роль | Что может делать | Кому назначать |
|---|---|---|
| **Creator** | Создавать/удалять категории и статьи, управлять структурой | Руководители, ответственные за БЗ |
| **Editor** | Создавать и редактировать статьи, но не менять структуру | Ключевые сотрудники, эксперты |
| **Commenter** | Читать статьи и оставлять комментарии | Большинство сотрудников |
| **Viewer** | Только читать | Новые сотрудники на испытательном сроке |

Поскольку база знаний находится в том же Base, что и CRM, роли применяются ко всему проекту. Если вам нужны разные права для CRM и базы знаний — создайте отдельный Base специально для документации.

### Советы по администрированию

Для того чтобы база знаний оставалась актуальной и полезной, важно выстроить процессы ее ведения. Назначьте **ответственного за каждый раздел** — это должен быть сотрудник, который лучше всего разбирается в данной теме и будет следить за актуальностью информации. Проводите **ежеквартальную ревизию**: просматривайте все статьи, помечайте устаревшие статусом «Архив» и обновляйте актуальные. Создайте **шаблон статьи** — отдельную запись с описанием того, как должна быть структурирована каждая статья (например, «Цель → Шаги → Пример → Частые ошибки»). Это обеспечит единообразие всей документации.

## Заключение

Вы создали полноценную, масштабируемую и интегрированную в ваши рабочие процессы базу знаний прямо в NocoDB. Этот инструмент поможет вашей команде работать эффективнее, быстрее находить нужную информацию и сохранять корпоративные знания на долгие годы.

Ключевые преимущества такого подхода: **единая среда** (CRM и документация в одном месте), **единые права доступа** (не нужно управлять двумя системами), **прямые связи** (статьи привязаны к сделкам и клиентам) и **нулевая стоимость** (NocoDB — open-source инструмент).
