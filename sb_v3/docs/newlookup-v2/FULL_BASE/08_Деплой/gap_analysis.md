# Gap Analysis: ТЗ v3.0 vs Реальный Код

Этот документ — точное сравнение того, что требовалось в ТЗ v3.0, и того, что есть в коде, с указанием конкретных действий для устранения разрыва.

---

| Агент | Требование из ТЗ v3.0 | Что есть в коде | Что нужно сделать (Gap) |
| :--- | :--- | :--- | :--- |
| **1. Mirror Bot** | Таблица `coupons` | Отсутствует | **Добавить** таблицу `coupons` и `CouponService`. |
| | Таблица `chats` с JSONB | Таблицы `seller_conversations` и `seller_chats` | **Оставить как есть.** Реализация в коде лучше. |
| | Доставка PDF как картинок | Доставка как PDF | **Изменить** `PDFWatermarkingService` для конвертации в картинки. |
| **3. Seller Bot** | Пакеты депозитов (e.g., `["cc","enroll"]`) | Пакеты `bank` и `cc` | **Переписать** `seller_deposit_service.py` для поддержки кастомных пакетов категорий. |
| **4. Worker Bot** | Таблица `worker_orders` | Общая таблица `orders` | **Добавить** таблицу `worker_orders` и перевести логику на нее. |
| | Поле `last_reminder_at` | Отсутствует | **Добавить** поле и `WorkerReminderService` для авто-напоминаний. |
| **5. Support Bot** | Роли как булевы флаги | Роли (`support`, `moderator`) + JSON permissions | **Оставить как есть.** Реализация в коде гибче. |
| **6. Admin Panel** | Единый `pricing_config` | Цены в БД (`service_prices`) и хардкоде | **Рефакторинг:** Создать единый `pricing_config` и перевести всю логику на него. |
| **8. Buyer Agent** | Гарантийные окна по ТЗ | Частично не совпадают | **Исправить** `guarantee_policy_service.py` в соответствии с ТЗ. |
| **9. NocoDB** | Единая таблица `audit_log` | Несколько таблиц (`order_messages`, `financial_operations`, ...) | **Рефакторинг:** Создать единый `NocoDBService.log_event` и перевести все логирование на него. |
