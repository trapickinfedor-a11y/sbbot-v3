## 🚨 КРИТИЧЕСКИЕ ПРОБЛЕМЫ (нужно исправить)

### 1. Нет cron-задачи для разблокировки эскроу
**Проблема:** Транзакции создаются со статусом `ON_HOLD` и `effective_at = NOW() + hold_hours`, но нигде нет scheduler-задачи, которая переводит их в `COMPLETED` после истечения холда.

**Последствие:** Деньги продавца навсегда заморожены. `LedgerReconciliationService` находит это как `issue`.

**Решение — добавить в `web_panel/main.py`:**
```python
async def _release_escrow_holds():
    """Release ON_HOLD transactions where effective_at has passed."""
    from sqlalchemy import update, select
    from shared.database.models import Transaction
    async with async_session_maker() as session:
        await session.execute(
            update(Transaction)
            .where(
                Transaction.status == "ON_HOLD",
                Transaction.effective_at <= datetime.utcnow(),
            )
            .values(status="COMPLETED")
        )
        await session.commit()

# В lifespan:
scheduler.add_job(_release_escrow_holds, "interval", minutes=30, id="escrow_release")
```

### 3. Buyer dispute ownership не проверяется
**Проблема:** При открытии спора не проверяется, что `order.user_id == callback.from_user.id`. Теоретически можно открыть спор по чужому order_id.

**Решение — добавить проверку в обработчик спора:**
```python
order = await session.get(Order, order_id)
if not order or order.user_id != callback.from_user.id:
    await callback.answer("❌ Access denied", show_alert=True)
    return
```

### 4. Составные индексы на горячих таблицах отсутствуют
**Проблема:** Таблица `orders` запрашивается по `user_id + status` сотни раз в секунду, но нет составного индекса.

**Последствие:** Full table scan при масштабировании → тормоза.

**Решение — добавить в модель `Order`:**
```python
__table_args__ = (
    Index("ix_orders_user_status", "user_id", "status"),
    Index("ix_orders_mirror_bot_status", "mirror_bot_id", "status"),
    Index("ix_orders_worker_status", "worker_id", "status"),
)
```

### 6. Нет защиты от отрицательного баланса при параллельных запросах
**Проблема:** `debit_user_balance` проверяет баланс перед списанием, но без `SELECT FOR UPDATE` — при параллельных запросах race condition возможен.

**Решение — `_lock_user` уже используется, нужно убедиться что он действительно делает FOR UPDATE:**
```python
async def _lock_user(session, user_id):
    return await session.scalar(
        select(User).where(User.user_id == user_id).with_for_update()  # ← проверить что это есть!
    )
```

### 7. Нет валидации markdown/html injection в сообщениях бота
**Проблема:** Пользовательский input (имена товаров, описания споров) вставляется в HTML-шаблоны без `escape()`.

**Последствие:** Telegram Bot API может получить битый HTML и выдать ошибку, или Telegram отобразит сломанное форматирование.

**Решение:**
```python
from html import escape
# Перед любым f-string с parse_mode="HTML":
safe_name = escape(product_name)
```

### 13. Seller quiet hours не проверяются при отправке уведомлений
**Проблема:** `quiet_hours_start/end` добавлены в модель и API, но при отправке уведомлений они НЕ проверяются в `weekly_report_service.py` и `auto_payout_service.py`.

**Решение — добавить хелпер:**
```python
def is_quiet_hours(seller: Seller) -> bool:
    if not seller.quiet_hours_start or not seller.quiet_hours_end:
        return False
    current_hour = datetime.utcnow().hour
    s, e = seller.quiet_hours_start, seller.quiet_hours_end
    return s <= current_hour < e if s < e else current_hour >= s or current_hour < e

# В weekly_report_service.py:
if is_quiet_hours(seller):
    continue  # skip — send tomorrow
```
