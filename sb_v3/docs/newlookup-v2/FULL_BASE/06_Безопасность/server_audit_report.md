### Архитектура проекта `newlookup`

Проект представляет собой **Telegram-бот сервис** с веб-панелью администратора. Структура:

```
/root/newlookup/
├── docker-compose.yml        — оркестрация всех сервисов
├── .env                      — переменные окружения
├── main_bot/                 — основной Telegram-бот (Python/aiogram)
├── support_bot/              — бот поддержки/исполнителей
├── web_panel/                — веб-панель администратора (FastAPI)
├── shared/                   — общие модули
├── mirror_bot/               — зеркальные боты
├── data/                     — данные приложения
├── media/                    — медиафайлы (14 MB)
└── scripts/                  — вспомогательные скрипты
```

**Стек технологий:**
- **Backend:** Python (aiogram для ботов, FastAPI для веб-панели)
- **База данных:** PostgreSQL 16
- **Кэш:** Redis 7
- **Контейнеризация:** Docker + Docker Compose
- **Безопасность:** Fail2Ban активен

### Обнаруженные проблемы

> **КРИТИЧНО: Конфликт Telegram webhook**  
> Контейнер `newlookup_main_bot` непрерывно выдаёт ошибку:  
> `TelegramConflictError: can't use getUpdates method while webhook is active`  
> Бот пытается получать обновления через polling, но активен webhook. Это означает, что **основной бот не получает сообщения от пользователей**.  
> **Решение:** Выполнить `deleteWebhook` через Telegram API или переключить бота на webhook-режим.

> **ВНИМАНИЕ: Попытки взлома SSH**  
> В логах зафиксированы постоянные попытки подбора пароля с адресов 167.99.194.87, 172.93.120.166, 92.222.22.180 и других. Fail2Ban активен, но рекомендуется дополнительно ограничить SSH по IP или перейти на ключи.

## Часть 2: Сервер NocoDB 91.214.78.88

### Статус подключения

> **Проблема с доступом к NocoDB серверу**

Сервер **91.214.78.88** имеет открытые TCP-порты (22, 80, 443, 3000, 8080, 8000), однако:

1. **SSH (порт 22):** Соединение устанавливается, но SSH-баннер не возвращается — сервер принимает соединение и сразу закрывает его. Возможные причины: нестандартный SSH-порт, firewall, или SSH настроен только на key-based аутентификацию.
2. **HTTP-порты (80, 443, 3000, 8080, 8000):** Соединение устанавливается, но сервер возвращает пустой ответ (`RemoteDisconnected`). Возможно, NocoDB слушает только на localhost (127.0.0.1), а не на 0.0.0.0.

### Что нужно проверить на сервере NocoDB

Подключитесь к серверу **91.214.78.88** через ваш SSH-клиент (PuTTY, Terminal) и выполните:

```bash
# 1. Проверить запущенные контейнеры
docker ps -a

# 2. Проверить на каком адресе слушает NocoDB
ss -tlnp | grep -E '8080|3000|80'

# 3. Посмотреть docker-compose NocoDB
find / -name "docker-compose*" 2>/dev/null | grep -v proc
cat /path/to/docker-compose.yml

# 4. Проверить логи NocoDB
docker logs <nocodb_container_name> --tail=20

# 5. Если NocoDB слушает только на 127.0.0.1 — исправить
# В docker-compose.yml изменить ports: с "127.0.0.1:8080:8080" на "0.0.0.0:8080:8080"
```

### Шаг 3: Настроить представления (Views)

#### Для таблицы "Сделки":
- **Канбан** → Group by: `Стадия` — воронка продаж
- **Grid "Мои сделки"** → Filter: `Менеджер` = текущий пользователь

#### Для таблицы "Задачи":
- **Календарь** → Date field: `Дедлайн`
- **Канбан** → Group by: `Статус`
- **Grid "Срочные"** → Filter: `Приоритет` = Срочно + `Статус` ≠ Готово

#### Для таблицы "Клиенты":
- **Grid "Лиды"** → Filter: `Статус` = Лид
- **Grid "VIP"** → Filter: `Тип` = VIP

#### Для таблицы "Статьи БЗ":
- **Gallery "Опубликованные"** → Filter: `Статус` = Опубликовано + Group by: `Категория`

### Шаг 4: Настроить аналитический Dashboard

В NocoDB перейдите в раздел **Dashboards** (иконка графика в левом меню) и создайте новый дашборд **"Аналитика CRM"**. Добавьте следующие виджеты:

| Виджет | Тип | Источник | Что показывает |
|---|---|---|---|
| **Активные сделки** | Number | Сделки | COUNT где Стадия ≠ Закрыта/Отказ |
| **Выручка этого месяца** | Number | Сделки | SUM Сумма где Стадия = Закрыта |
| **Воронка продаж** | Bar Chart | Сделки | COUNT по Стадии |
| **Источники клиентов** | Pie Chart | Клиенты | COUNT по Источнику |
| **Задачи по статусам** | Donut Chart | Задачи | COUNT по Статусу |
| **KPI сотрудников** | Bar Chart | Сотрудники | KPI по Имени |
| **Бюджет кампаний** | Bar Chart | Маркетинг | Бюджет vs Потрачено |

### Шаг 5: Настроить Workflows (автоматизация)

В разделе **Automations** создайте:

1. **Уведомление о новой сделке** → Trigger: Record created (Сделки) → Action: Send email менеджеру
2. **Задача при смене стадии** → Trigger: Field changed (Стадия) → Action: Create record в Задачах
3. **Напоминание о дедлайне** → Trigger: Scheduled (каждый день 9:00) → Action: Email исполнителям просроченных задач

## Часть 4: Исправление проблемы с main_bot

> Это **только рекомендация** — выполнять только если вы уверены в действии.

Для исправления конфликта webhook/polling в `newlookup_main_bot`:

```bash
# Подключиться к серверу 147.45.45.85
ssh root@147.45.45.85

# Посмотреть токен бота
grep MAIN_BOT_TOKEN /root/newlookup/.env

# Удалить webhook (заменить TOKEN на реальный токен)
curl "https://api.telegram.org/bot<TOKEN>/deleteWebhook"

# Перезапустить только main_bot (НЕ весь стек)
cd /root/newlookup && docker compose restart main_bot
```
