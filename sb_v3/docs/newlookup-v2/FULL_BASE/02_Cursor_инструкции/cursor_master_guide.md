## Newlookup: Мастер-Гайд для Реализации через Cursor v2.0

**Задача:** Этот документ — исчерпывающее руководство для AI-ассистента (Cursor) по созданию проекта Newlookup. Он содержит не только пошаговый план, но и архитектурные паттерны, примеры кода и детализированные промты для каждого этапа.

---

### 1. Архитектурные Принципы для ИИ

*   **Clean Architecture:** Код должен быть разделен на слои: `domain` (модели), `repository` (доступ к данным), `service` (бизнес-логика), `api` (эндпоинты). Это упрощает тестирование и поддержку.
*   **Repository Pattern:** Вся работа с БД должна идти через `Repository`. Сервисы не должны напрямую вызывать SQLAlchemy. Это позволяет легко мокать репозитории в тестах.
*   **Dependency Injection:** FastAPI должен управлять зависимостями. Используй `Depends()` для внедрения репозиториев и сервисов в эндпоинты.
*   **Асинхронность:** Весь I/O-bound код (работа с БД, API-запросы, работа с ботом) должен быть асинхронным (`async/await`).

### 2. Пошаговый План Реализации (Детализированный)

#### **Этап 1: Ядро Системы**

1.  **Структура Проекта:**
    *   `/app`: Бэкенд FastAPI.
        *   `/app/api`: Эндпоинты.
        *   `/app/services`: Бизнес-логика.
        *   `/app/repositories`: Работа с БД.
        *   `/app/models`: SQLAlchemy модели.
        *   `/app/schemas`: Pydantic схемы.
    *   `/bots`: Код для Telegram-ботов.
    *   `/migrations`: Alembic миграции.
2.  **Настройка Окружения:**
    *   `pyproject.toml` с `poetry`.
    *   `docker-compose.yml` (Postgres, Redis, Backend, Celery Worker, Celery Beat).
3.  **База Данных:**
    *   Написать SQLAlchemy модели на основе `database_schema_v2.sql`.
    *   Настроить Alembic и создать первую миграцию.

> **Промпт 1.1 (Структура и Модели):**
> "Создай структуру проекта Newlookup с папками `/app`, `/bots`, `/migrations`. Внутри `/app` создай подпапки `api`, `services`, `repositories`, `models`, `schemas`. Затем, проанализируй `database_schema_v2.sql` и создай асинхронные SQLAlchemy 2.0 модели для всех таблиц в `/app/models`. Настрой Alembic для асинхронных миграций и сгенерируй первую миграцию."

#### **Этап 2: Пользователи и Аутентификация**

1.  **Репозиторий Пользователей:** `UserRepository` с методами `get_by_email`, `create`, `get_by_id`.
2.  **Сервис Пользователей:** `UserService` с бизнес-логикой регистрации.
3.  **API Аутентификации:** Эндпоинты `/login`, `/register`, `/refresh` с JWT.

> **Промпт 2.1 (Регистрация):**
> "Реализуй полный флоу регистрации пользователя. Создай `UserRepository` с методом `create`. Создай `UserService`, который принимает `UserCreate` Pydantic-схему, хеширует пароль с помощью `passlib` и вызывает репозиторий для сохранения пользователя. Создай FastAPI-эндпоинт `POST /api/v1/auth/register`, который использует этот сервис. Используй Dependency Injection для внедрения зависимостей."

#### **Этап 3: Продукты и Каталог**

1.  **Репозиторий Продуктов:** `ProductRepository` с методами для CRUD и фильтрации.
2.  **FSM в Seller Bot:** Хендлеры для пошаговой загрузки товаров.
3.  **Отображение в Mirror Bot:** Хендлеры для навигации по категориям и просмотра товаров.

> **Промпт 3.1 (FSM для Загрузки):**
> "Напиши FSM-хендлер для `aiogram 3` для загрузки товара типа 'Selfreg BA'. Используй состояния для пошагового запроса: Название, Описание, Цена, Файл. После получения всех данных, сделай POST-запрос к API для создания продукта. Используй `State` и `FSMContext`."

#### **Этап 4: Покупки и Финансы**

1.  **Сервис Заказов:** `OrderService` с логикой создания заказа, холда средств.
2.  **Интеграция с BTCPay:** `BTCPayService` для создания инвойсов.
3.  **Celery-задачи:** Задача для проверки статуса платежа.

> **Промпт 4.1 (Создание Заказа):**
> "Напиши метод `create_order` в `OrderService`. Он должен:
> 1. Принять `user_id` и `product_id`.
> 2. Проверить, достаточно ли у пользователя средств на балансе.
> 3. Создать запись в таблице `orders` со статусом `pending`.
> 4. Заморозить средства на балансе пользователя (создать транзакцию `hold`).
> 5. Вернуть созданный заказ. 
> Вся операция должна быть выполнена в рамках одной транзакции БД."

#### **Этап 5: Продвинутые Модули**

1.  **История Покупок:** Реализовать API и хендлеры на основе `purchase_history_module.md`.
2.  **Купоны:** Реализовать API и хендлеры на основе `coupons_and_promo.md`.

> **Промпт 5.1 (История Покупок API):**
> "Используя `purchase_history_module.md`, реализуй FastAPI-эндпоинт `GET /api/v1/orders/my` с фильтрацией по `category_id` и `seller_id`, а также пагинацией. Используй Pydantic-схемы из документа для ответа."

### 3. Советы для Cursor

*   **Контекст — это главное:** Всегда держи открытыми `newlookup_srs_v22_FINAL.md` и соответствующий модуль (`coupons_and_promo.md`, etc.), чтобы у ИИ был полный контекст.
*   **Атомарные Задачи:** Не пытайся реализовать весь сервис за один промт. Двигайся по одному методу или эндпоинту за раз.
*   **Тесты в первую очередь (TDD):** Сначала попроси ИИ написать `pytest`-тест для сервиса или эндпоинта, а потом — саму реализацию. Это гарантирует качество.

> **Пример TDD-промта:**
> "Напиши `pytest`-тест для FastAPI-эндпоинта `POST /api/v1/coupons/activate`. Он должен проверить:
> 1. Успешную активацию с валидным кодом (статус 200).
> 2. Ошибку 404, если купон не найден.
> 3. Ошибку 400, если купон уже активирован.
> 4. Ошибку 400, если срок действия купона истек.
> Используй `TestClient` и мокай зависимости, где это необходимо."
