# Стратегия разработки Newlookup с помощью Cursor AI

Этот документ описывает наиболее эффективный подход к написанию кода для системы Newlookup с использованием AI-ассистента Cursor. Цель — максимизировать скорость и качество разработки, используя полное техническое задание (ТЗ) как единый источник правды.

---

## 1. Философия "Мастер-Промта"

Ключ к успеху — **непрерывный контекст**. Вместо того чтобы задавать Cursor короткие, изолированные вопросы, необходимо на каждой итерации предоставлять ему максимально полную картину проекта.

**Основной принцип:**

1.  **Загрузите всё ТЗ:** Перед началом работы откройте файл `newlookup_srs_v12_full.md` в Cursor.
2.  **Выделите всё:** Перед тем как задать любой вопрос или попросить написать код, всегда выделяйте **весь текст ТЗ** (Ctrl+A) и добавляйте его в чат с AI (`@`-символ или аналогичная функция).
3.  **Будьте конкретны:** После добавления полного контекста ТЗ, давайте чёткую и конкретную команду, ссылаясь на номера разделов из документа. Например: `«Напиши модели SQLAlchemy для всех таблиц из раздела 3.2, используя код из этого же раздела как образец»`.

Это гарантирует, что AI всегда будет в курсе всех взаимосвязей, названий полей, ролей и бизнес-логик, что минимизирует ошибки и ускоряет разработку.

## 2. Оптимальная файловая структура проекта

Правильная структура — залог масштабируемости. Вместо одного большого файла, проект разбивается на логические модули. Это позволяет работать над каждым ботом и сервисом изолированно.

```
newlookup/
├── app/                      # Основная папка с кодом
│   ├── __init__.py
│   ├── core/                 # Ядро системы
│   │   ├── __init__.py
│   │   ├── config.py         # Конфигурация (из env)
│   │   └── db.py             # Настройки базы данных и сессий
│   │
│   ├── db/                   # База данных
│   │   ├── __init__.py
│   │   ├── models/           # Модели SQLAlchemy
│   │   │   ├── __init__.py
│   │   │   ├── user_related.py # user, seller, marketer, admin, worker
│   │   │   ├── product_related.py # все seller_*_items, brute_bank_*, esim_plans
│   │   │   └── system.py       # transaction, withdrawal, coupon, ticket, etc.
│   │   └── repository.py     # Функции для работы с БД (CRUD)
│   │
│   ├── bots/                 # Логика всех ботов
│   │   ├── __init__.py
│   │   ├── mirror_bot/
│   │   │   ├── __init__.py
│   │   │   ├── handlers.py     # Обработчики команд и сообщений
│   │   │   ├── keyboards.py    # Функции для генерации клавиатур
│   │   │   └── states.py       # Состояния FSM
│   │   ├── seller_bot/       # (аналогичная структура)
│   │   ├── support_bot/      # (аналогичная структура)
│   │   ├── marketer_bot/     # (аналогичная структура)
│   │   ├── worker_bot/       # (аналогичная структура)
│   │   └── main_bot/         # (аналогичная структура)
│   │
│   ├── services/             # Бизнес-логика, не привязанная к ботам
│   │   ├── __init__.py
│   │   ├── payments.py       # Логика работы с платежными системами
│   │   ├── products.py       # Логика управления товарами
│   │   └── withdrawals.py    # Логика обработки вывода средств
│   │
│   ├── web/                  # Веб-часть (Admin Panel, Seller Mini App)
│   │   ├── __init__.py
│   │   ├── main.py           # FastAPI приложение
│   │   ├── routers/          # Роутеры API
│   │   │   ├── __init__.py
│   │   │   ├── admin_panel.py
│   │   │   └── seller_mini_app.py
│   │   └── schemas.py        # Pydantic схемы для API
│   │
│   └── utils/                # Вспомогательные функции
│       ├── __init__.py
│       └── texts.py            # Все тексты и переводы
│
├── main.py                   # Главный запускающий файл (запуск всех ботов)
├── requirements.txt          # Зависимости
└── .env                      # Переменные окружения
```

## 3. Пошаговый процесс разработки и промты

Разработка ведётся итерационно, в соответствии с приоритетами из раздела 14 ТЗ. Каждый шаг — это отдельный промт для Cursor.

**Важно:** Перед каждым промтом не забывайте выделять всё ТЗ!

### Шаг 1: Настройка проекта и База Данных (Приоритет P0)

1.  **Создание структуры:**
    > **Промт:** «Создай файловую структуру проекта, как описано в разделе 2 этого ТЗ. Все файлы должны быть пустыми, кроме `__init__.py` в каждой папке.»

2.  **Конфигурация:**
    > **Промт:** «Напиши код для `app/core/config.py`. Используй Pydantic `BaseSettings` для загрузки всех переменных окружения, перечисленных в разделе 2.3 ТЗ.»

3.  **Модели SQLAlchemy:**
    > **Промт:** «Напиши код для `app/db/models/`. Раздели все модели из раздела 3 ТЗ на 3 файла, как указано в файловой структуре: `user_related.py`, `product_related.py`, `system.py`. Используй SQLAlchemy 2.0 с аннотациями типов. Код моделей из раздела 3.2 используй как образец.»

4.  **Настройка БД:**
    > **Промт:** «Напиши код для `app/core/db.py`. Создай асинхронный движок SQLAlchemy (`create_async_engine`) и фабрику сессий (`async_sessionmaker`), используя настройки из `app/core/config.py`.»

### Шаг 2: Ядро Mirror Bot (Приоритет P0-P1)

1.  **Главный файл:**
    > **Промт:** «Напиши код для `main.py`. Он должен инициализировать и запускать всех 6 ботов (Mirror, Seller, Support, Marketer, Worker, Main) в асинхронном режиме, используя `asyncio.gather`. Для каждого бота создай свой экземпляр `Dispatcher` из Aiogram.»

2.  **Обработчики `start`:**
    > **Промт:** «Напиши код для `app/bots/mirror_bot/handlers.py`. Реализуй обработчик команды `/start`, который реализует логику из разделов 4.1 и 4.2 ТЗ: принятие правил, регистрация пользователя, обработка реферальной ссылки (`?start=ref_XXXXX`). Создай соответствующие функции в `app/db/repository.py` для работы с пользователями.»

3.  **Клавиатура главного меню:**
    > **Промт:** «Напиши код для `app/bots/mirror_bot/keyboards.py`. Создай функцию, которая генерирует динамическую клавиатуру главного меню на основе данных из таблицы `mirror_menu_categories` (раздел 4.2 ТЗ). Функция должна принимать язык пользователя и возвращать готовую клавиатуру.»

### Шаг 3: Система Купонов и Платежей (Приоритет P1)

1.  **Логика купонов:**
    > **Промт:** «Напиши код для `app/bots/mirror_bot/handlers.py` и `app/db/repository.py` для реализации логики применения купонов (раздел 4.3, REQ-MB-008). Создай FSM для ввода купона. Все проверки (срок действия, лимиты, одноразовость) должны быть реализованы.»

2.  **Интеграция платежей:**
    > **Промт:** «Напиши код для `app/services/payments.py`. Создай классы для интеграции с BTCPay Server и Helecat, как указано в разделе 4.3 ТЗ. Реализуй функции для создания счёта на оплату и проверки статуса платежа.»

### Шаг 4: Seller Bot и Загрузка Товаров (Приоритет P1)

1.  **Депозит продавца:**
    > **Промт:** «Напиши код для `app/bots/seller_bot/handlers.py`. Реализуй флоу внесения депозита $600 для продавцов (раздел 5.1 ТЗ). Используй сервис `app/services/payments.py`.»

2.  **FSM-конфигураторы:**
    > **Промт:** «Для `app/bots/seller_bot/` создай FSM-конфигураторы для загрузки всех 9 типов товаров, как описано в разделе 5.3 ТЗ. Для каждой категории создай свой файл с хендлерами. Например, `handlers_selfreg_ba.py`, `handlers_cc.py` и т.д. Вся логика должна строго соответствовать спецификациям из раздела 13 ТЗ.»

### Шаг 5: Support Bot и Флоу Модерации (Приоритет P1-P2)

1.  **Ролевая модель:**
    > **Промт:** «Создай middleware для Aiogram, которое будет проверять роль сотрудника из таблицы `admins` (раздел 8.1 ТЗ) перед выполнением команд в Support Bot.»

2.  **Флоу вывода средств:**
    > **Промт:** «Напиши хендлеры для `app/bots/support_bot/handlers.py`, реализующие полный флоу обработки заявок на вывод средств для роли `finance` (раздел 8.2 ТЗ). Заявки должны браться из единой таблицы `withdrawal_requests`.»

3.  **Флоу модерации товаров:**
    > **Промт:** «Напиши хендлеры для `app/bots/support_bot/handlers.py` для модерации товаров (раздел 8.4 ТЗ). Модератор должен получать уведомление, видеть карточку товара и иметь кнопки "Одобрить" / "Отклонить" / "Редактировать".»

### Шаг 6: Admin Panel (FastAPI) и Seller Mini App (Приоритет P2)

1.  **Настройка FastAPI:**
    > **Промт:** «Напиши базовый код для `app/web/main.py`, создающий приложение FastAPI. Напиши код для `app/web/schemas.py`, содержащий Pydantic-схемы для всех моделей БД. Напиши роутер `app/web/routers/admin_panel.py` с эндпоинтом для логина администратора (JWT-авторизация).»

2.  **Эндпоинты для управления:**
    > **Промт:** «Создай в `app/web/routers/admin_panel.py` CRUD-эндпоинты для управления категориями меню (раздел 11.2 ТЗ) и купонами (раздел 11.4 ТЗ).»

3.  **Конфигуратор Brute Bank:**
    > **Промт:** «Создай эндпоинты для `Admin Panel`, которые позволят управлять группами Brute Bank в соответствии с конфигуратором из раздела 11.7 ТЗ.»

## 4. Дополнительные советы для эффективности

-   **Разбивайте задачи:** Если промт получается слишком большим (например, «напиши весь Seller Bot»), разбивайте его на более мелкие, логические части («напиши флоу депозита», «напиши FSM для загрузки Selfreg BA» и т.д.).
-   **Используйте `@-ссылки` на файлы:** Когда просите доработать существующий код, используйте `@` для ссылки на конкретный файл в вашем проекте. Например: `«Доработай код в @app/bots/seller_bot/handlers.py, добавив обработку...»`.
-   **Тестируйте итерационно:** После каждого сгенерированного блока кода запускайте и проверяйте его. Если есть ошибка, отправляйте в Cursor код и текст ошибки с промтом `«Исправь ошибку»`.
-   **Рефакторинг:** После того как основной функционал готов, можно дать общую команду: `«Проанализируй весь код проекта на предмет дублирования и предложи рефакторинг для улучшения структуры»`.
